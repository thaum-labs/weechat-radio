weechat-radio:$ wire protocol

      
For people writing software. If you only want to chat, see weak signals instead.


      
This hub build (17 Sep 2026, ce4a108) uses version 2 on radio (KISS) and internet (WebSocket). Version 1 frames are still decoded. msg_id is not sent on v2: the receiver recomputes it from origin, dest, seq, and the uncompressed body.

!! at the start of a message is emergency (sent twice). ! is priority. Unacked frames are retried and the modem steps down: QPSK 1/2 → RDM-1200S → RDM-600S → RDM-300S → MFSK-32R.


      
BEACON

      
Type BEACON. Body is UTF-8 B|<mode>|<khz> (example B|internet-radio|144950). The kHz field is the origin’s dial so gateways and the map know which band a station is on. Legacy B|<mode> is still decoded. Beacons heard on RF are also tagged with the receiving station’s own dial.


      
Callsign packing

      
6 bits per character, 8 characters, alphabet:

      
 space A–Z 0–9 / - ~

      
Guests: ~ALICE. Amateur callsigns must look like a callsign (letter and digit).


      
ACK

      
Type ACK. Body is the 8-byte msg_id of the original, plus an optional 9th byte: receiver SNR in dB as a signed integer. Relayed with TTL. Unacked messages are retransmitted up to rf.max_retries times (default 3). Retry hold times are jittered ±25% so stations that collided do not retry in lockstep. Group ACKs wait a random 0–ack_dither_ms (default 800 ms) before keying; direct ACKs are not dithered.


      
HAVE / WANT

      
Body is a comma-separated list of hex msg ids in a closed group window.


      
FRAG

      
Type FRAG (10). Group messages on HF, or any payload larger than the PHY frame, are split into Reed–Solomon shards. Any k of k+m reconstruct the original (default 2 of 3). Gateways forward fragments as they hear them; the hub reassembles from shards received via different gateways.


      
Federation (reserved)

      
Hub-to-hub uses the same envelope and the same msg_id dedupe. Not enabled in v1.
