weechat-radio:$ modes

      
Four ways to chat. Switch with /radio mode <name> or press F2 in the TUI.


      

      

        

          
internet

          
Radio off. You talk to the hub only. Fine for trying the program with no hardware.

        

        

          
internet-radio

          
Radio is primary. Internet fills gaps. This station is a gateway for others.

        

        

          
radio

          
Radio chat only. Frames never go on the hub or the LAN mesh. The map still updates if telemetry is on. Switching here asks you to confirm.

        

        

          
radio-plus

          
Chat stays off the hub from this computer. A nearby gateway that hears you may forward. Map metadata still POSTs if telemetry is on.

If the hub dies

      
      
Changing mode starts or stops hub chat and the radio path immediately. In internet-radio every chat still goes on RF; the hub and LAN mesh are used only when the destination is not recently heard on this dial over radio (groups: no member heard here). #bulletin always offers the hub and LAN. The live map still gets signed metadata (not message text) whenever [telemetry] url is set, including in radio. Clear that URL to stay off the map.

      
If you are in internet-radio and the hub goes away, radio keeps working. The status bar says Internet down, radio only. Traffic that still needed the hub waits in an internet hold and goes out when the hub returns. That is separate from the RF retry hold queue.


      
Email

      
Email is not another operating mode. The map pin keeps its mode colour, and an e beside that logo means mail moved recently. You can send from internet, internet-radio, or radio-plus with a gateway callsign in setup. radio has no path to the internet, so Email stays grey. Email.


      
Weak-signal behaviour

      
On a faint or fading path the program retries your message and asks modem73 for a slower waveform. The status bar shows TX (current waveform) and RETRY. Presets: hf-good, hf-poor, hf-weak, hf-deep, vox-safe (always MFSK-32R).

      
Operator steps: weak signals. Versus JS8 / FT8 / Olivia: compare modes. Packet layout: wire protocol.


      
Busy channel

      
When several stations talk at once, frames would otherwise pile onto the modem and key over each other. Two layers stop that:

      
    
        
  1. modem73 CSMA is on for every preset. The modem waits for a quiet carrier before PTT.
    2. 
        
  2. The air queue in wcr serialises our own traffic. It waits while the channel is busy, spreads retries and group ACKs, skips beacons when occupancy is high, and leaves a gap after each TX so an ACK can be heard.
    3. 
      

      
The status bar PTT field shows wait while a frame is held. OCC is occupancy 0–100. QUEUE includes how many frames sit in the air queue.

      
[rf]
csma = true
slot_ms = 100
quiet_ms = 300
max_defer_ms = 15000
emergency_max_defer_ms = 3000
turnaround_ms = 250
congested_pct = 60
ack_dither_ms = 800
beacon_jitter_s = 15
retry_jitter = true


      
Gateway knobs

      
In wcr.toml:

      
[gateway]
rf_egress = true          # put internet traffic on the air
third_party = "deny"      # guest (~nick) traffic on RF: allow or deny

      
Stations on different frequencies use two gateways and the hub. Diagrams: cross-frequency chat.
