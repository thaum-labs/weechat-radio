v1.0.25 fixes the QA #402 blockers and adds the #403 and #404 work. Run `wcr update` to get it.

## What changed since v1.0.24

- modem73 comes back by itself: after a GUI preset change, if it crashes, or if its link to the station closes. `wcr restart` with the desktop app running now really restarts the radio and says so only once the modem is running again (#402).
- A line typed while modem73 is down stays queued. It is no longer marked sent and spends no retry; it goes out when the modem is back. Status, the desktop app and the terminal view say "modem not running" (#402).
- Bluetooth radio (VR-N76): a link that comes up with no audio is reconnected, and on a second stall the Bluetooth link is reset. `/status` shows `bt_rx_stalls`. Quitting closes the audio link cleanly so the next start finds it free (#402).
- Lines to a station that stopped answering are held after two unanswered retries ("peer quiet") until that station is heard again. Nothing is dropped. A soft warning shows when 10 or more lines are queued (#402).
- Activity bar: red bars while a Bluetooth radio transmits, floor bars while it is idle (#402).
- Live chat: each part of a long message has its own block, yellow while on the air, green when that part is confirmed, red if it failed, with "k of n parts confirmed". Your unconfirmed lines are pale gold. Click a callsign under HEARD to open a private chat (#403).
- Apple Silicon Macs: wcr and wcr-gui are ad-hoc signed in the release, and the installer re-signs them (#404).

The Live Chat on-air pacing, presets and framing did not change.
