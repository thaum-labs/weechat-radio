v1.0.20-rc13 is a release candidate. Get it with `wcr update --rc`. It carries everything from rc12 back to rc6.

## One transmission per burst, VOX included

rc12 on Windows with VOX keyed a file or mail one frame at a time, about 4 to 5 s each, and the Pi keyed in groups of 4. The cause is in modem73 itself: it keys at most 4 frames per transmission, and only 1 on VOX, each with the full VOX lead and tail.

- The bundled modem73 has a new wcr patch (`keyed-bursts`) with a `burst_frames` setting. wcr turns it on for a file burst or a mail block and off afterwards, so the whole block goes out in one transmission: one VOX lead at the start, a short tone between frames to keep VOX open, and one tail at the end.
- The rest between mail blocks (`[rf] duty`) still applies.
- Chat files and mail use the same path.
- On VOX, `ptt_on` in `/status` means "modem73 is sending audio", not that the radio keyed. During a burst it stays on for the whole burst.

## Cancel stops what the modem already holds

- Cancel on a mail or a chat file now drops the frames already handed to modem73 (new `clear_tx_queue` command). Only the frame on the air finishes.
- New Cancel button on your own file line while it is being sent (desktop, modem73 layout and Pi page). `/radio filecancel <id>` does the same.

## Fixes

- The burst status line ("38/38 · burst keyed, waiting for report") becomes "38/38 · complete" once the file is [ok], or just the bar if it failed.
- `[x2]` on a file that arrived first time: the pieces' retry clock started when the burst was queued, so a piece could go again before the report came. The clock now starts once the burst has keyed.
- Airtime estimate: "~3 min 10 s on vhf-fast (49 frames in 2 bursts, incl. 20 s rest)" instead of "~3 min (49 bursts)".
- A refused file says: switch to vhf-fast (2 m or 70 cm, a steady link of about 10 dB) to send attachments up to 512 KB. Changing preset rechecks the file, so Send comes back without attaching it again.
- Mail Send stays off until To is a valid address and Subject is filled in, with a hint why.
- Pi page On the air: file rows show "piece 3/38 · name · 220 B of 7.7 KB · burst" or the report, with SNR and frame size. The station log has one line per file piece heard.

## What to test

1. On VOX (Windows, vhf-fast), send an 8 KB picture and a 64 KB mail: each burst or block keys once.
2. Cancel a mail and a chat file mid-burst: TX stops within one frame, nothing more reaches the far end.
3. A first-try file shows `[ok]` with no `[x2]`, and the status line ends with "complete".
4. Refused file on the desktop and Pi mail forms, then change preset to vhf-fast: Send comes back.
5. Mail with no To or Subject: Send is off.
6. rc13 to rc12 and rc11, both ways.
