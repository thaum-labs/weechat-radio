v1.0.19-rc2 is a release candidate. Get it with `wcr update --rc`.

## What changed since v1.0.19-rc1

**Bluetooth audio: no more false "no capture data" (#359)**

- On the VR-N76 / VR-N7600 Bluetooth path, wcr's bridge sends modem73 audio in 20 ms blocks and is the audio clock. modem73 2.5.0 calls the link stalled when no block arrives within 20 ms, so a block only a millisecond late made it log `Network audio: no capture data, pacing transmit locally` (QA counted 4097 of these in one session) and show the link as stalled.
- Our modem73 patch now waits 250 ms before it treats the link as stalled. That is how our own 2.4.8-wcr network audio behaved. Linux, Pi, macOS and Windows.
- We checked what this did to transmitted audio: in the two-bridge test the audio sent to the radio is the same sample for sample with and without the stalls, so this was log noise and a wrong status, not damaged transmit audio. It does not explain the Mac → Pi first-try misses in #359 on its own.
- The bundled modem73 is still 2.5.0-wcr. The radio signal is unchanged, so rc2 talks to rc1 and v1.0.18.
