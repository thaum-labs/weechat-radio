v1.0.16 is the final release of the v1.0.16 series. It is the same station code as v1.0.16-rc10, plus a stricter address check from the hub mail fix (#300). Run `wcr update` to get it. On rc3 or later, press Update on the web page or in the desktop app.

## What changed since v1.0.15 (rc1 to rc10)

**Radio+ mail gateway**
- Setup's "Mail gateway" shows only in Radio+ mode, with one line explaining it (#274).
- **Auto** is the new default: your station asks over the air which internet-radio gateways hear you, the hub gives the best three a reply slot each, and your station picks the one with the best two-way signal. It asks again at start, after a band or preset change, about hourly, and when the pick stops answering. A typed callsign still pins one gateway (#275, rc1).
- The outbox and mail timeline show the gateway used ("via TF101"); the send bar shows "Finding a mail gateway" while it looks.
- When the hub refuses a gateway's ask or Check mail, the log now says why (key registered to another station, bad signature, clock out) (#278, rc2).

**Gateway mode: chat and mail, or mail only (#272, rc6)**
- A Pi gateway can be set to **Mail only**: it still shows chat but keys nothing for other stations' chat. Set it on the Pi web page, with `/gateway mail-only`, or `[gateway] mode` in `wcr.toml`. Chat and mail stays the default.

**Updates and restarts without a terminal (#280, rc3 to rc5)**
- Pi web page **Software** card and desktop app **Software** window: Update, and Restart to finish.
- Restarts wait until the radio is quiet, never force it, and bring the station back as you left it. A new version that fails to start rolls back by itself. A restart you ask for no longer counts as a failed start.
- On a Pi, `wcr setup` finishes the install: web page password and "Start the station now and at every boot?".
- `wcr setup` run again keeps every saved setting. Setup pages save themselves. Bluetooth audio setup saves no sound card.
- New `wcr status` and `wcr restart`.

**Bluetooth radios (rc7, rc8)**
- IN and OUT meter the radio's own Bluetooth audio, not the PC's speakers or microphone.
- Loud hiss at squelch 0 on Bluetooth reads "good"; the only advice left is to lower RX gain to 0 dB when it is above.

**Desktop app station panel (rc8, rc10)**
- RX GAIN and TX LVL are two knobs; the mail gateway is a three-segment MAIL GW bar; HELP is folded into one line; IN advice moved into IN's hover tip so the panel stops shifting.

**Pi web page (rc6, rc9)**
- The waterfall no longer stays empty after login; Gateway mode and Mail gateway choices are readable in Safari.

**Hub mail relay (#300, live on the hub since its merge)**
- Mail through the hub needs the callsign's registered key, with per-station, per-address and daily limits, size caps (subject 200 characters, body 4 KB) and exactly one To address. Stations now refuse a To with a comma, semicolon or a second @.

## Known issues / backlog

- #271 (v1.0.16 backlog) items not done in this series: random retry wait after a collision, stock modem73 v2.5.0, occasional on-air overlaps, Pi RX clipping after its own TX, Pi missing frames over Bluetooth.
- The Radio+ station itself does not yet show why the hub refused it (needs a new over-the-air reply).
