v1.0.16-rc3 is a release candidate. Get it with `wcr update --rc`.

## What changed since v1.0.16-rc2

**Updates and restarts without a terminal (#280)**
- Pi web page: a new **Software** card. It shows "Update available (x)" with an **Update** button, and "Installed x / Running y" with **Restart to finish** when the two differ. After an update the page reloads on the new version and you stay logged in.
- Desktop app: the same in a **Software** window (click the version at the bottom left; an amber link appears in the top bar when there is something to do).
- No sudo: `wcr web` restarts itself in place on the newly installed version (same process, same systemd service, same user). `wcr restart` asks it to.
- Safe restarts: it waits until the radio is quiet (nothing sending or receiving, empty air queue, no mail being passed, no beacon due in the next 10 s, for 5 s in a row), never forces it, and gives up after 15 minutes with a message. The station comes back on or off as you left it.
- Automatic rollback: if the new version keeps failing to start, or its station does not stay up for 60 s, the previous version comes back by itself and the page or app says "Rolled back to x: …".
- The config is copied to `wcr.toml.before-update` before every update. The SHA-256 check on downloads is unchanged.
- Release candidates and the rollback test are command-line only: `wcr update --rc`, `wcr update --test-rollback`. A station already on an rc is offered the next rc on the page.
- CLI: `wcr update` installs, restarts safely and ends with one line ("Updated to 1.0.16, running, radio idle."). New `wcr status` and `wcr restart`.
- Pi/Linux: the installer and `sudo wcr web install` link `wcr` into `/usr/local/bin`, so `ssh pi@host wcr status` works.

**Coming from rc2 or older:** those versions cannot restart themselves, so do one last `wcr update --rc`, then `sudo systemctl restart wcr-web` (or reboot the Pi). After that, use the page.
