v1.0.19 is the final release of the v1.0.19 series: everything from v1.0.19-rc1 to rc3, with no changes since rc3. Run `wcr update` to get it. On an RC, press Update on the web page or in the desktop app.

## What changed since v1.0.18 (rc1 to rc3)

**modem73 moves to v2.5.0 (#357, rc1)**
- The bundled modem73 is now **2.5.0-wcr** on Linux, Raspberry Pi, macOS and Windows (it was 2.4.8-wcr, and 2.4.2-wcr on Windows). `wcr update` moves it with the app; no manual steps.
- Network audio for the VR-N76 / VR-N7600 Bluetooth path is now built into modem73 upstream, so our own patch for it is gone. Same wire format: wcr's Bluetooth bridge is unchanged.
- Still patched in by us: the level meter readings and the waterfall (Linux, Pi, macOS), TX level down to 1 %, the CSMA sync slot fix from #241 (all platforms), and encoding a frame before the busy test so PTT keys straight after "Channel clear" (Linux, Pi, macOS).
- The radio signal itself is unchanged between 2.4.8 and 2.5.0, so a station on v1.0.19 and one on v1.0.18 still hear each other.
- Upstream change: with VOX PTT, modem73 now sends one frame per keying instead of up to two back to back.

**Bluetooth "no capture data" log flood fixed (#359, rc2 and rc3)**
- modem73 2.5.0 logged `Network audio: no capture data, pacing transmit locally` whenever a 20 ms block from wcr's Bluetooth bridge was a millisecond late (thousands of lines per session). It now logs that, and reports the link stalled, only after 250 ms without audio.
- Bluetooth transmit pacing is exactly as upstream 2.5.0 does it (rc3). On air, Mac → Pi over the VR-N76 is back to first try at 7–8 dB.
- New off-air check `transmit_audio_matches_the_reference_build` (in `btaudio` tests) compares the audio sent to the radio by two modem73 builds: level, length and gaps.

**QA on air (#359):** Mac ↔ Pi 20/20 delivered, Windows ↔ Pi 4/4 first try, 0 `no capture data` lines on every station.
