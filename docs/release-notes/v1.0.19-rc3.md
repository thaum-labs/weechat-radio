v1.0.19-rc3 is a release candidate. Get it with `wcr update --rc`.

## What changed since v1.0.19-rc2

**Bluetooth transmit back to rc1's behaviour (#359)**

- On air, rc2's Mac → Pi signal over the VR-N76's Bluetooth audio was about 8 dB weaker than rc1's, with the same radio and the same Pi. The only difference between those builds is how modem73 paces transmit audio when a block from wcr's Bluetooth bridge is late.
- rc3 puts that pacing back exactly as upstream modem73 2.5.0 (and rc1) do it.
- The log fix from rc2 stays: modem73 logs `Network audio: no capture data, pacing transmit locally`, and reports the link stalled, only after 250 ms without audio from the bridge, not after every 20 ms block that is a millisecond late.
- New off-air check `transmit_audio_matches_the_reference_build` (in `btaudio` tests). It sends one frame through the Bluetooth bridge with two modem73 builds and compares what the radio is sent: level, length and gaps. Run it with `WCR_TEST_MODEM73=<new modem73> WCR_TEST_MODEM73_REF=<old modem73> cargo test -p wcr --lib --no-default-features -- --ignored transmit_audio_matches`.
- The bundled modem73 is still 2.5.0-wcr. The radio signal format is unchanged, so rc3 talks to rc2, rc1 and v1.0.18.
