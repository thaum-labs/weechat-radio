v1.0.16-rc6 is a release candidate. Get it with `wcr update --rc`. On rc3, rc4 or rc5, press Update on the web page or in the desktop app.

Same code as v1.0.16-rc5 plus PR #287, which landed just after the rc5 tag.

## What changed since v1.0.16-rc5

**Gateway mode: chat and mail, or mail only (#272)**
- An internet-radio gateway (a Pi gateway) can be set to **Mail only**. It still hears chat and shows it, but it keys nothing for other stations' chat: no relays, no receipts, no retries, no group history sync and no hub chat carried onto the air.
- Mail, beacons and the lines the operator types on the gateway itself still go out as before.
- **Chat and mail** is the default, so nothing changes unless you pick Mail only.
- Three ways to set it, all saved in `wcr.toml` as `[gateway] mode`:
  - Pi web page: the new **Gateway mode** box on the Station card (internet-radio only), then **Save**. Works while the station is stopped too; the next Start uses it.
  - Station: `/gateway mail-only` or `/gateway chat-and-mail` (`/gateway` alone says the current mode).
  - By hand: `[gateway] mode = "mail-only"` in `wcr.toml`.
- A mail-only gateway says so: a "gateway mail only" fact on the web page, `gateway_mode` in `/status`, and `| gateway mail-only` on `/radio status`.

**Pi web page waterfall (#271)**
- A spectrum request that never answered could leave the waterfall empty until a reload (about one login in 60). Requests now give up after 2 s and the next one tries again. A page that opens on a held row also paints straight away.

**Tests (#271)**
- The mail harness waits for the modem link before its first message (a macOS start-up flake).
