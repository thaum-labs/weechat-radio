v1.0.20-rc12 is a release candidate. Get it with `wcr update --rc`. It carries everything from rc11 back to rc6.

## Chat file bursts finish on time

rc11's on-air test took about 8 minutes for a file estimated at about 37 seconds. Three causes, all fixed:

- After every item it sent, the station waited a fixed time (about 18 s on vhf-fast) before the next one, because modem73 never reports frames sent. It now goes on as soon as modem73 is idle. A resend or a report no longer waits minutes in the queue.
- The receiver reported 6 s after the last piece it heard, which fired in the middle of a burst when the sending radio paused. It now reports 1 s after the file's last piece (which ends every burst), or after 15 s of quiet if that piece was lost.
- The sender acted on a report that arrived while its burst was still going, and a stale resend could go out after a newer one. Reports are now only acted on once the burst has been keyed, a new resend replaces any older one still queued, and a receiver's newer report replaces its older one. A receiver that already has the whole file says so at once.

## Radio type: rests between long transmissions

- New setting **Radio type**: Handheld (default), Mobile or Base. A handheld rests the radio 20 s after each 2 minute block of a big mail so it does not heat-fade, a mobile 10 s, a base not at all.
- While resting, the send window says "Resting the radio 20 s so it does not overheat" (Pi page: "Resting radio 20 s").
- The airtime estimate includes the rests.
- Desktop: RADIO row in the station panel. Pi page: Station section. Chat: `/duty handheld|mobile|base`. Or `[rf] duty` in wcr.toml.
- Chat files never need a rest: even 8 KB goes in well under a minute.

## Fixes

- The "sending NAME to CALL … [ok] on the file line means …" note goes away once the file is [ok] or failed (desktop and Pi page).
- Pi page: the File button shows when the page opens on a direct chat, and it is the same size as Send.
- `/status` shows how old its SNR is, for example `SNR 12.0 (25 min ago)`. It is the last frame decoded, not a live reading.
- Email airtime no longer says "~about 3 min".
- `/file` help gives the real limits (4 KB, pictures 8 KB on vhf-fast).

## What to test

1. On `vhf-fast`, send an 8 KB picture in a direct chat: it should finish in about the estimate.
2. Repeat with a forced loss: only the missing pieces go again, and the sender stops as soon as the far end has the whole file.
3. Send a 64 KB or 128 KB mail on Handheld: "Resting the radio" shows between blocks. On Base it does not.
4. Set Radio type on the desktop and on the Pi page, and check `[rf] duty` in wcr.toml.
5. The refused file in the Email popup (desktop and Pi), Cancel on mail and file, and rc12 to rc11.
