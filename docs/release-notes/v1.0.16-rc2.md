## What changed since v1.0.16-rc1

**Clear reason when the hub turns away a Radio+ ask or Check mail (#278)**
- QA's 401s on #278 were the hub correctly refusing M7TJF/M: the on-air run used a fresh scratch home with a new identity key, and the hub has M7TJF/M bound to the Mac's original key. Nothing in rc1 was broken, and the hub's key check is unchanged.
- The 401 now says why, and the gateway's log shows it:
  - `gateway ask: M7TJF/M is registered to a different key on the hub (this station's key 08821326…). Use the original identity.key or re-register.` (same wording for `mail pull:`)
  - `bad signature` (signed for another callsign or other messages, or not signed by that key)
  - `clock more than 10 minutes out`
- The key is shown as its first 8 hex digits of the public key, never the secret seed.
- New tests go through the real hub handlers and key table with a /M callsign: the bound key's ask and Check mail/Get are accepted; another key, a wrong signature and a stale clock are refused, for both the ask and the pull, and nothing gets re-bound.
- The hub part is live as soon as this is merged. The station code only moved the ask and pull signing into shared functions the tests use; nothing changes on the air.
- Not in this rc (backlog): showing the reason on the Radio+ station itself (it would need a new reply over the air).
